# Phase 8: Full-text ingestion — Discuss

## Goal
Index the full text of the 10 corpus papers instead of only their abstracts. Parse
the arXiv PDFs, chunk them along document structure, embed them with a stronger
model, and show citations with paper, section and page.

## Scope
### In
- Manifest: extend `data/papers/*.json` with `arxiv_id` and `pdf_url`. A download
  script fetches the PDFs into a gitignored `data/pdfs/`.
- Parse script, run on the host: PDFs go to a gitignored `data/parsed/<paper_id>.json`
  holding sections and page numbers in a parser-agnostic format. The parser
  dependency is an optional extra and stays out of the runtime image.
- Parser spike: Docling vs PyMuPDF4LLM on 2–3 papers. Compare section detection,
  page numbers, tables and captions, and speed. The ADR records the measured result.
  PyMuPDF's AGPL licence counts against it.
- Structure-aware chunker. The abstract is its own chunk. References and
  acknowledgments are dropped.
- Tables become their own chunks: the caption plus the table as markdown, with
  section and page. A table over the token limit is split by rows, with the header
  row repeated in each piece.
- Figure captions are indexed as source text, tagged as captions. No
  model-generated image descriptions.
- Ingest reads the parsed cache. A paper without a cache file falls back to its
  abstract. The Compose `ingest` service mounts `data/parsed/` read-only.
- Default embedder `bge-small-en-v1.5` (384-dim) via `EMBEDDING_MODEL`. The vector
  dimension comes from the model, not a constant.
- `Citation` gets `paper_id`, `section`, `page` and `chunk_index`. One citation per
  retrieved chunk, so several can come from the same paper.
- The generation prompt labels evidence with paper and section. The UI shows
  paper + section + page.

### Out
- Retrieval evaluation, golden set, threshold/top-k tuning by metrics (Phase 9).
- Reranking and hybrid/BM25 (Phase 10).
- Splitting `EmbeddingProvider` into query and document embedding, bge query
  prefix, domain-specific embedders (Phase 9).
- OCR. Figure descriptions generated by a vision model (Docling picture
  description): slow on CPU, and generated text is not source evidence. Parked.
- Corpus expansion. Grounding validator changes (Phase 11).
- Parsing inside Docker. Committing PDFs or parsed text (redistribution).

## Requirements
- R1 The corpus can be reproduced from committed files: manifest plus download and
  parse scripts. PDFs and parsed text stay gitignored and out of Docker images
  (`.dockerignore`).
- R2 Every chunk carries `paper_id` (file stem), `section`, `page`, `chunk_index` and
  `chunk_type` (`text` | `table` | `caption`). Chunks fit the embedder's 512-token limit.
- R3 Point IDs are deterministic from `(paper_id, chunk_index)`. Re-running ingest
  is idempotent, and `--overwrite` re-indexes.
- R4 A fresh clone with no parsed cache still completes `docker compose up`
  end to end, abstract-only with a logged warning.
- R5 The new `Citation` fields are additive with defaults. The `/query` and
  `/query/stream` shapes otherwise stay unchanged, and existing tests and the
  `scripts/llm_bench` fixtures keep working.
- R6 Evidence passed to generation fits the model context. Nothing is silently
  truncated.
- R7 The test suite needs no PDFs, no parser, no network and no model download.
  Chunker and cache loading are tested with small fixtures.
- R8 The five quality gates pass. Adding parser dependencies leaves pip-audit clean.

## Assumptions
- A1 All 10 papers have an arXiv version. `conch` (2307.12914) and
  `cxr_vlm_generation` (likely RoentGen, 2211.12737) are journal versions whose
  preprints may differ from the published text.
- A2 Docling runs on Python 3.14 (`docling-parse` ships cp314 wheels).
- A3 About 10 papers × 20–40 pages gives a few hundred chunks. Ingest and query
  latency on CPU stay small with bge-small.

## Unknowns
- U1 Parser quality on these PDFs (two-column layouts, headings, page mapping,
  results tables, figure captions as separate items).
  Resolved by the spike as the first Execute task; ADR written after.
- U2 Whether the preprints for `conch` and `cxr_vlm_generation` match the published
  papers. Resolved in Plan by checking arXiv; the mismatch gets recorded in the manifest.
- U3 Chunk size and overlap. Plan sets a starting value (about 300–400 tokens, small
  overlap, split at section boundaries); Phase 9 tunes it.
- U4 `score_threshold=0.4` (`app/retrieval/search.py`) was tuned for MiniLM, and bge
  scores cluster higher. Resolved in Execute by looking at the score distribution;
  provisional value until Phase 9.
- U5 Ollama `num_ctx` is unset, so the server default applies. Resolved in Plan:
  set `num_ctx` explicitly or cap the evidence by tokens.
- U6 Docling's model downloads and its transitive dependencies (pip-audit,
  install size). Resolved in Plan, before the spike.
- U7 Section label format (leaf heading vs. path, numbering normalisation). Resolved
  in Plan; it has to be stable, because Phase 9 labels are at paper + section level.

## Risks
- Parser output can be noisy (merged columns, headers or footers in the text, wrong
  heading levels), and that degrades chunks silently. Mitigation: the spike plus a
  quick manual check of one parsed file per paper.
- bge-small retrieves number-heavy table chunks less reliably than prose. The
  caption in the chunk helps; Phase 9 measures it.
- With per-chunk citations, one paper can fill all top-k slots. Accepted for now;
  Phase 9 shows whether a per-paper cap is needed.
- `confidence` means something different after the switch to bge. The UI and docs
  must not present it as calibrated.
- Heavy parser dependencies could leak into the runtime image or the CI install
  through the lockfile. Keep them in an optional extra.

## ADRs to write

- ADR-0021: Chunking strategy (text, table and caption chunks) and chunk/citation
